# WirelessComprehensiveWorkTerminalMenu / Screen 结构拆分方案

- 日期：2026-11-06
- 现状：菜单类 5100 行、247 个方法、15 个嵌套类；界面类 6500 行、290 个方法、17 个嵌套类。性能与崩溃审计里八成以上的发现都落在这两个文件。
- 目标：把它们拆成按功能域划分的协作类，行为保持不变，每拆一个单元编译一次、提交一次，单元测试全过。不改包结构以外的任何对外接口（网络包、数据组件、注册名）。

## 1. 菜单类的拆分单元

按方法名统计，菜单类的方法分布如下：

| 功能域 | 方法数 | 目标类 |
|---|---|---|
| 手动工作区（合成台、锻造台、铁砧，含两个 MenuBridge、结果槽、替换与补料） | 52 | `menu/WcwtManualWorkspace` |
| 样板编码（预览、切石、倍增、处理合并、复制替换、编码与上传入口） | 48 | `menu/WcwtPatternEncoding` |
| 元件工作台（分区、清除、复制模式、配置缓存） | 12 | `menu/WcwtCellWorkbench` |
| 样板供应器与上传 | 17 | 大部分已在 `WcwtPatternUploadTargets`，剩余并入 |
| 工具包、Curios、装饰盔甲槽位 | 17 | `menu/WcwtEquipmentSlots` |
| 其余（槽位布局、quickMove、broadcastChanges、数据槽） | 77 | 留在菜单类 |

拆法：协作类持有菜单的引用（或一个只暴露所需能力的小接口），方法整体移动，菜单类保留一行委托。嵌套的槽位类随其功能域一起移动。先拆最独立的元件工作台，再拆手动工作区，最后拆样板编码。

## 2. 界面类的拆分单元

| 功能域 | 方法数 | 目标类 |
|---|---|---|
| 样板管理区（行重建、搜索、命中测试、渲染、提示、槽位同步，含 9 个 record/enum） | 74 + 约 40 个辅助 | `client/gui/PatternManagementView` |
| 样板编码区（模式按钮、槽位布局、切石结果、倍增按钮） | 27 | `client/gui/PatternEncodingView` |
| 工具包（槽位、记忆槽覆盖层、管理区内的工具包） | 21 | `client/gui/ToolkitView` |
| 扩展 UI 按钮与面板 | 16 | `client/gui/ExtendedUiButtons` |
| 仓库视图、收藏、类型过滤、init、JEI 排除区、子界面 | 其余 | 留在界面类 |

拆法同上。界面类的渲染方法要注意调用顺序与 `firstFrameOfTick` 这类共享状态，共享状态放在界面类上通过访问器暴露。先拆工具包，再拆编码区，最后拆样板管理区。

## 3. 风险与前提

- 这是纯移动式重构，但两个文件各超过五千行，每个单元的移动都会产生上千行的 diff。如果计划把改动回合并到上游 lhy512103/AE2-WCWT，这些 diff 会让 PR 很难审阅，建议先把前面的修复提交单独成 PR，再谈重构。
- 重构前应先完成一次游戏内运行验证，保证起点是可运行的。
- 重构期间不混入行为改动；发现的问题先记下，拆完再修。
